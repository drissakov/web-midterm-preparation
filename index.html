01HTML, теги, атрибуты и DOMКак разметка превращается в структуру страницы.

Суть темы

HTML — язык разметки: он описывает смысл и структуру содержимого. CSS задаёт внешний вид и расположение. Браузер разбирает HTML в дерево объектов — DOM. Элемент может содержать текст, другие элементы и атрибуты.

В <a href="events.html">Events</a> тег a задаёт ссылку, href — адрес, а текст между тегами — её имя. Атрибуты id и class помогают находить элемент и оформлять его. Один элемент может иметь несколько классов; ID должен быть уникальным в документе.

У img, input, meta и link нет закрывающего тега. Остальные элементы нужно правильно вкладывать. Комментарий виден в исходнике, но не выводится как содержимое страницы. HTML не является языком программирования общего назначения.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<!-- Карточка команды: комментарий для разработчика -->
<article class="team-card featured" id="team-spirit">
  <h3>Team Spirit</h3>
  <p>Демонстрационная карточка команды.</p>
  <a href="events.html#event-list">Найти турнир</a>
</article>

article → отдельная карточка; class → повторяемое оформление; id → уникальный адрес; href → переход.

Скажи на защите

HTML задаёт структуру и смысл. Браузер строит DOM, а CSS оформляет элементы этого дерева.

Типичная ошибка

Вкладывать ссылку в ссылку или кнопку внутрь ссылки. Интерактивные элементы не должны конфликтовать.

Где показать в EsportsHub: Все шесть HTML-страниц; карточки в teams.html и players.html.

02Каркас HTML-документаDOCTYPE, lang, head, charset, viewport, title и body.

Суть темы

<!DOCTYPE html> включает стандартный режим обработки HTML. Корневой html содержит весь документ. lang сообщает основной язык текста: en для англоязычного EsportsHub, ru для этого конспекта.

head содержит метаданные и подключения: кодировку UTF-8, настройки viewport, заголовок вкладки и CSS. body содержит видимую страницу. title — название вкладки и документа; h1 — главный заголовок внутри страницы. Они решают разные задачи.

Viewport сообщает мобильному браузеру использовать ширину устройства в CSS-пикселях и исходный масштаб 1. Без него адаптивная вёрстка на телефоне может отображаться как уменьшенная широкая страница. Комментарий с авторами не заменяет видимые имена в footer.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0">
  <!-- Created by Damir, Alina and Aisha -->
  <title>Events | EsportsHub</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <h1>Find your next competition</h1>
</body>
</html>

Путь css/style.css вычисляется от HTML-файла. Браузер загружает общий stylesheet для всех страниц.

Скажи на защите

Я использую стандартный HTML-каркас, UTF-8, язык документа и viewport. Общий CSS подключается в head.

Типичная ошибка

Путать title и h1, забывать viewport или использовать одинаковое неинформативное название всех вкладок.

Где показать в EsportsHub: Начало index.html, events.html, teams.html, players.html, rankings.html и contact.html.

03Семантика, заголовки и текстКогда использовать header, nav, main, aside, section и article.

Суть темы

header — вводная область, nav — навигация, main — основное уникальное содержимое, aside — связанные дополнительные ссылки или информация, footer — завершение и авторство. В проекте один основной видимый main на странице.

section объединяет тему и обычно имеет заголовок. article подходит для самостоятельной единицы: карточки события или профиля. div и span нейтральны по смыслу; их удобно использовать для группировки и оформления, когда специальная семантика не нужна.

Один содержательный h1 обозначает тему страницы, h2 — основные разделы, h3 — подразделы. Уровень выбирают по структуре, размер — через CSS. p обозначает абзац; strong важность, em смысловое ударение. Не используй повторяющиеся br для отступов.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<header><nav aria-label="Main navigation">…</nav></header>
<main id="main-content">
  <h1>Players</h1>
  <section aria-labelledby="profiles-title">
    <h2 id="profiles-title">Featured profiles</h2>
    <article><h3>donk</h3><p>Sample profile.</p></article>
  </section>
</main>
<aside aria-label="Player links">…</aside>
<footer>Damir · Alina · Aisha</footer>

Семантика помогает понять страницу и человеку, и вспомогательным технологиям. Символ … здесь сокращает учебный пример.

Скажи на защите

Я делю страницу на смысловые области и выстраиваю заголовки по вложенности содержания.

Типичная ошибка

Заменять все элементы на div или выбирать h3 только потому, что он визуально меньше h2.

Где показать в EsportsHub: Общая структура .page-layout на каждой странице.

04Списки, ссылки и якоряНавигация между страницами и внутри страницы.

Суть темы

ul — список без обязательного порядка, например игры или характеристики игрока. ol — последовательность: найти турнир, проверить условия, зарегистрировать команду. Каждый пункт оформляется через li.

href="players.html" ведёт к соседнему файлу, href="#donk" — к ID в текущем документе, href="players.html#donk" — к профилю на другой странице. Абсолютный URL включает протокол и домен. В GitHub Pages путь /images/a.jpg начинается от корня домена и может пропустить префикс /EsportsHub/.

Ссылка выполняет переход, кнопка запускает действие или отправку формы. href="#" просто переводит к началу документа и не заменяет реализованное действие. aria-current="page" сообщает о текущей странице; цвет и подчёркивание дают видимое состояние. Регистр имён файлов важен при публикации.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<ol>
  <li>Найти турнир</li>
  <li>Проверить условия участия</li>
  <li>Подготовить регистрацию команды</li>
</ol>
<ul><li>Game: CS2</li><li>Role: AWPer</li></ul>

<a href="players.html#monesy">Профиль m0NESY</a>
<a href="events.html" aria-current="page">Events</a>

ID monesy должен существовать именно в players.html. Относительные пути сохраняют работу сайта в подпапке проекта.

Скажи на защите

Порядок важен в ol, а ul группирует равноправные пункты. Якорь связывает href с уникальным id.

Типичная ошибка

Писать C:\\Users\\… в href, путать регистр файла или создавать действие View profile без реального адреса профиля.

Где показать в EsportsHub: events.html#event-guidance — ol; players.html — списки профилей; общий navbar — шесть страниц.

05Изображения без сжатия и растяженияЕстественные пропорции, осознанный crop, alt и круглый аватар.

Суть темы

У файла есть собственные размеры и отношение ширины к высоте. Обычное изображение должно уменьшаться в контейнере с сохранением этой пропорции: max-width: 100% и height: auto. HTML-атрибуты width/height, соответствующие исходнику, помогают браузеру заранее резервировать место.

object-fit: cover сохраняет пропорции, заполняет заданную область и обрезает края. contain показывает изображение целиком, но может оставить пустое место. Они не исправляют исходный файл и полезны, когда размер области уже ограничен. Для карточки, галереи и аватара crop допустим внутри явно заданной рамки с aspect-ratio. Квадрат плюс border-radius: 50% даёт круг.

alt объясняет смысл изображения; декоративному ставят alt="". Не пиши «картинка картинки». SVG удобен для схем, JPEG для фотографий, WebP/AVIF — для эффективного сжатия; расширение должно соответствовать реальному формату. Сохраняй источник и лицензию чужого изображения.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
/* Обычный контент: без обрезания */
img { max-width: 100%; height: auto; }

/* Намеренная область превью */
.card-media {
  aspect-ratio: 4 / 3;
  overflow: hidden;
}
.card-media img {
  width: 100%;
  height: 100%;
  object-fit: cover;
}

/* Круглый аватар: рамка квадратная */
.avatar { aspect-ratio: 1; border-radius: 50%; overflow: hidden; }

Изображение 1200×800 при ширине 600px имеет естественную высоту 400px. Высота 200px без корректного crop исказит пропорции.

Скажи на защите

Обычные картинки сохраняют естественное отношение сторон. Обрезка используется только в специально ограниченных media-контейнерах.

Типичная ошибка

Назначать всем img width:100% и фиксированную height:200px или применять cover ко всем обычным иллюстрациям.

Где показать в EsportsHub: .feature-image, .hero-image img; .player-card-media, .gallery-media, .carousel-media и .profile-avatar.

06Таблица и адаптивное переполнениеcaption, thead, tbody, tr, th, td и scope.

Суть темы

Таблица предназначена для данных, связанных по строкам и столбцам. tr задаёт строку, th — заголовочную ячейку, td — данные. thead и tbody отделяют шапку от тела, caption даёт название таблицы.

scope="col" связывает заголовок со столбцом, scope="row" — со строкой. colspan и rowspan объединяют ячейки, но усложняют структуру и нужны только по смыслу.

На телефоне таблица может быть шире доступного места. Помести её в подписанную область с overflow-x: auto, а при необходимости добавь tabindex="0" для клавиатурного прокручивания. Ограничивай переполнение этой областью; не прячь его у всей страницы, маскируя проблему.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<section class="table-wrap" aria-label="Sample ranking" tabindex="0">
  <table>
    <caption>Demo ranking</caption>
    <thead><tr>
      <th scope="col">Team</th>
      <th scope="col">Game</th>
      <th scope="col">Points</th>
    </tr></thead>
    <tbody><tr>
      <th scope="row">Team Spirit</th>
      <td>CS2</td><td>2450</td>
    </tr></tbody>
  </table>
</section>

/* В CSS */
.table-wrap { max-width: 100%; overflow-x: auto; }
table { width: 100%; min-width: 480px; border-collapse: collapse; }

Минимальная ширина удерживает данные читаемыми, а overflow-x:auto создаёт локальную прокрутку только при необходимости.

Скажи на защите

В рейтинге таблица отражает данные. Заголовки и caption объясняют их, а отдельная область прокрутки сохраняет мобильную страницу.

Типичная ошибка

Использовать таблицу для всей вёрстки сайта или делать все ячейки td, теряя заголовки.

Где показать в EsportsHub: rankings.html#ranking-method — четыре столбца, scoped-заголовки и демонстрационные очки.

07HTML-формы и нативная валидацияlabel, id, name, required, email, select, textarea и submit.

Суть темы

label for должен совпадать с id поля. name — имя значения при отправке, а placeholder — лишь пример ввода: он не заменяет подпись. Поля text и email, список select, многострочная textarea и кнопка type="submit" составляют форму обращения.

required запрещает пустой ввод; type="email" проверяет допустимый формат, но не существование адреса. minlength, maxlength и pattern задают дополнительные ограничения. autocomplete помогает заполнению. Радиокнопки с одинаковым name задают один выбор, checkbox — независимые отметки. Группу объединяют в fieldset с legend.

action определяет адрес отправки, method="get" помещает значения в URL, post обычно передаёт их в теле запроса. POST сам по себе не шифрует данные — это задача HTTPS. Проверка браузера не заменяет серверную проверку. В EsportsHub mailto открывает почтовый клиент; хранения и подтверждённой доставки нет.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<form action="mailto:info@esportshub.com"
      method="post" enctype="text/plain">
  <label for="visitor">Name</label>
  <input id="visitor" name="name" type="text" required>
  <label for="mail">Email</label>
  <input id="mail" name="email" type="email" required>
  <label for="topic">Topic</label>
  <select id="topic" name="topic" required>
    <option value="">Choose a topic</option>
    <option value="feedback">Feedback</option>
  </select>
  <label for="message">Message</label>
  <textarea id="message" name="message" required></textarea>
  <button type="submit">Open email draft</button>
</form>

Пустое value первого option позволяет required потребовать осмысленный выбор. Кнопки без отправки получают type="button".

Скажи на защите

Форма имеет связанные подписи и обязательные поля. Браузер проверяет ввод, а mailto передаёт подготовку письма почтовому приложению.

Типичная ошибка

Обещать сохранение заявки на сервере, которого нет, или утверждать, что email-валидация подтверждает владельца адреса.

Где показать в EsportsHub: contact.html#contact-form; объяснение статического поведения видно рядом с кнопкой.

08Авторство, биографии и общая структураЧто именно нужно показать по заданию.

Суть темы

Комментарий об авторах — часть исходника, биография — видимое содержимое, footer — повторяемое завершение страницы. Это три разные вещи. В биографии лучше объяснить вклад каждого участника, а не ограничиться общим «мы сделали сайт».

Общие navbar и footer должны сохранять порядок ссылок и терминологию. Текущую страницу отмечают классом и aria-current. Sidebar дополняет навигацию контекстом: например, на Players ведёт к профилям и галерее, а не просто повторяет весь navbar.

Переиспользование общего CSS уменьшает расхождения между шестью файлами. В статическом HTML одинаковая разметка шапки повторяется вручную; если меняешь пункт меню, проверь все страницы.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
<!-- Created by Damir, Alina and Aisha -->
<section id="team">
  <h2>About the Team Members</h2>
  <section><h3>Damir</h3><p>Home and Events.</p></section>
  <section><h3>Alina</h3><p>Teams and Players.</p></section>
  <section><h3>Aisha</h3><p>Rankings and Community.</p></section>
</section>
<footer><p>Damir · Alina · Aisha</p></footer>

Вклад участника объясняется через конкретные страницы и решения, которые он может показать в коде.

Скажи на защите

У проекта единые навигация и footer. Биографии фиксируют распределение работы между тремя участниками.

Типичная ошибка

Оставить одного автора в footer некоторых страниц или назвать sidebar отдельной несвязанной навигацией.

Где показать в EsportsHub: contact.html#team; имена Damir, Alina и Aisha в footer всех шести страниц.

09CSS: подключение, каскад и наследованиеПочему браузер выбирает именно это значение свойства.

Суть темы

CSS-правило состоит из селектора и блока объявлений свойство: значение;. Внешний файл подключают через link; один stylesheet можно применять к нескольким страницам. Внутренний style и атрибут style существуют, но для задания основной CSS должен быть внешним и читаемым.

Каскад разрешает конфликт нескольких правил. Упрощённо для обычных авторских правил в одном слое: выигрывает более специфичный селектор, а при равенстве — более позднее объявление. До специфичности браузер учитывает происхождение, важность и каскадные слои. Поэтому формула «последнее правило всегда выигрывает» неверна.

Некоторые свойства, например color и font-family, наследуются. margin, padding и border обычно не наследуются. Явное правило на дочернем элементе важнее полученного по наследованию значения. Пользовательские свойства --accent позволяют хранить общие значения. !important используй точечно с понятной причиной.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
/* css/style.css */
:root { --accent: #b51e22; }
body { font-family: system-ui, sans-serif; color: #2b1710; }
.card { padding: 1rem; color: var(--accent); }
.card p { line-height: 1.6; }

/* В HTML, сначала библиотека, затем свой CSS */
<link rel="stylesheet" href="bootstrap.min.css">
<link rel="stylesheet" href="css/style.css">

10Четыре типа селекторов и специфичностьElement, class, ID и descendant — обязательные примеры.

Суть темы

Элемент p выбирает все абзацы; класс .player-card — повторяемый компонент; ID #contact-form — уникальную форму; потомок .card p — абзацы на любой глубине внутри карточки. Селектор .card > p выбирает только непосредственного ребёнка.

11Box model: content, padding, border, marginКак вычислить реальный размер блока.

Суть темы

Каждый элемент занимает прямоугольную область. Изнутри наружу: content → padding → border → margin. Padding увеличивает внутренний отступ, margin отделяет элемент от соседей. Фон рисуется под внутренними отступами, но не в margin.

При box-sizing: content-box заданная width — ширина содержимого. Для width 240px, padding 20px и border 2px итоговая рамка имеет ширину 284px: 240 + 40 + 4. При border-box та же рамка равна 240px, а содержимое — 196px. Margin в width не включается в обоих случаях.

max-width ограничивает размер, min-width задаёт нижнюю границу. У Flex/Grid-элементов min-width: 0 часто необходим, чтобы длинный контент мог сжаться. Вертикальные margin соседних обычных блоков иногда схлопываются; между flex/grid-элементами такого схлопывания нет.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
* { box-sizing: border-box; }

.card {
  width: 240px;
  max-width: 100%;
  padding: 20px;
  border: 2px solid #e6cf8b;
  margin: 16px 0;
}

Короткая универсальная настройка box-sizing полезна. Огромный универсальный блок с размерами и отступами для всех элементов мешает управлять компонентами.

Скажи на защите

Border-box включает padding и border в заданную ширину. Поэтому компоненты легче вписывать в адаптивные контейнеры.

Типичная ошибка

Считать margin внутренним отступом или объяснять ширину 100% без учёта padding и border.

Где показать в EsportsHub: Глобальный box-sizing; padding, border и margin в .player-card, .bio и #contact-form.

12Типографика, цвета и единицы измеренияКак сделать интерфейс читабельным и последовательным.

Суть темы

font-family задаёт стек шрифтов, font-size размер, font-weight насыщенность, line-height межстрочный интервал. Системный стек быстро загружается; тяжёлый декоративный шрифт не подходит для всех абзацев и полей. Ограниченная длина строки облегчает чтение.

  line-height: 1.6;
  color: #2b1710;

13Поток, display, position и overflowКак понять источник наложений и горизонтальной прокрутки.

Суть темы

В обычном потоке блоки располагаются один за другим. display: block создаёт блочную коробку; inline участвует в строке; inline-block позволяет задавать размеры, оставаясь в строке. Flex и Grid задают отдельные способы раскладки детей.

position: relative сохраняет место элемента в потоке и позволяет смещение. absolute убирает его из потока; содержащий блок обычно определяется ближайшим позиционированным предком, хотя некоторые свойства тоже его создают. fixed обычно привязывает элемент к viewport. sticky сначала остаётся в потоке, затем удерживается у заданной границы своего scroll-контейнера.

overflow: auto добавляет прокрутку при необходимости, hidden обрезает. display: none убирает элемент из раскладки и обычно из дерева доступности; visibility: hidden сохраняет место. Большой z-index действует в контексте наложения, а не безусловно поверх всего сайта.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР

.scroll-region { overflow-x: auto; }
.media { overflow: hidden; }
.flex-child { min-width: 0; }
.long-text { overflow-wrap: anywhere; }

Sticky может не работать как ожидается, если у предка своё overflow или не хватает пространства для перемещения.

Скажи на защите

Сначала я нахожу элемент, выходящий за контейнер, затем исправляю его размер или локальное переполнение.

Типичная ошибка

Исправлять сломанную ширину глобальным overflow-x:hidden: так можно просто спрятать обрезанные элементы.

Оси, размеры карточек, равные высоты, навигация, именованные области и галерея.

Модель раскладки
01Flexbox: контейнер, элементы и осиjustify-content и align-items зависят от направления.

Суть темы

display: flex делает непосредственных детей контейнера flex-элементами. Flexbox управляет раскладкой прежде всего вдоль одной главной оси. flex-direction: row располагает элементы по строке; column — по столбцу. Направление row учитывает направление письма.

justify-content распределяет свободное место вдоль главной оси, align-items выравнивает элементы по поперечной. Поэтому «justify всегда горизонтально» — неверно: при column главная ось вертикальная. gap задаёт интервалы между элементами, но не внешний отступ контейнера.

flex-wrap: wrap разрешает перенос. align-content распределяет строки многострочного контейнера при наличии свободного места; для единственной строки он не заменяет align-items. align-self переопределяет выравнивание отдельного элемента.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
.nav-row {
  display: flex;
  flex-direction: row;
  align-items: center;
  justify-content: space-between;
  gap: 1.5rem;
  flex-wrap: wrap;
}

Для шапки row + align-items:center выравнивают бренд и ссылки по вертикали. Space-between использует свободное место между ними.

Скажи на защите

Flexbox управляет элементами вдоль главной оси. Направление оси задаёт flex-direction, а выравнивание — justify-content и align-items.

Типичная ошибка

Объяснять оси как постоянные «горизонтальную и вертикальную», не учитывая flex-direction.

Где показать в EsportsHub: Flexbox-сочетание .navbar > .container и .navbar-nav; .players-container.

02flex-grow, flex-shrink и flex-basisОткуда берётся ширина карточки и почему она может уменьшиться.

Суть темы

flex-basis задаёт исходный основной размер элемента перед распределением места. flex-grow — коэффициент распределения положительного свободного места, flex-shrink — коэффициент уменьшения при нехватке места. Shrink учитывает и базовые размеры: значение 1 не означает одинаковое уменьшение в пикселях для разных карточек.

Сокращение flex: 0 0 30% означает: не растягивать, не сжимать, начать с 30%. flex: 1 обычно используют для равного деления доступного места между гибкими элементами. Итог зависит также от min/max-размеров, содержимого и количества элементов.

У трёх карточек есть два промежутка. При gap 20px ширина каждой — calc((100% - 40px) / 3). Если поставить каждой 33.333% и добавить gap, суммарная ширина превысит 100%. min-width: 0 позволяет длинному содержимому не удерживать ненужную минимальную ширину.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
.players-container { display: flex; flex-wrap: wrap; gap: 20px; }
.player-card {
  flex: 0 0 calc((100% - 40px) / 3);
  min-width: 0;
}
@media (max-width: 991.98px) {
  .player-card { flex-basis: calc((100% - 20px) / 2); }
}
@media (max-width: 767.98px) {
  .player-card { flex-basis: 100%; }
}

В каждой строке ширины карточек плюс промежутки точно укладываются в 100% контейнера.

Скажи на защите

Я рассчитываю flex-basis с учётом gap. Media queries меняют число карточек в строке с трёх на две и одну.

Типичная ошибка

Писать flex:1 и ожидать обязательно три карточки на каждой ширине: это не правило количества колонок.

Где показать в EsportsHub: .players-container и .player-card в css/style.css.

03Равная высота карточек и действия снизуВнешний Flexbox раскладывает карточки, внутренний — их содержимое.

Суть темы

Требуемая карточка содержит изображение, заголовок, текст и полезное действие. У внешнего контейнера align-items: stretch растягивает карточки до высоты строки, если их размер по поперечной оси не зафиксирован. Равная высота относится к одной строке; строки с разным содержимым могут отличаться.

Внутри карточки удобно задать display: flex; flex-direction: column. Ссылка с margin-top: auto использует оставшееся место над собой и прижимается вниз. Это сохраняет ровное положение действий без ручной высоты каждого абзаца.

Hover может слегка сдвигать карточку и добавлять тень. transform визуально перемещает элемент без перерасчёта обычного потока. Не прячь важную информацию только в hover: у телефона и клавиатуры другие способы взаимодействия. Для reduced-motion убирай несущественное движение.

РАЗОБРАТЬ КОД · УЧЕБНЫЙ ПРИМЕР
.player-card {
  display: flex;
  flex-direction: column;
  transition: transform .2s, box-shadow .2s;
}
.player-card .action { margin-top: auto; }
.player-card:hover { transform: translateY(-5px); }
@media (prefers-reduced-motion: reduce) {
  .player-card { transition: none; }
  .player-card:hover { transform: none; }
}

Внешняя раскладка и внутренняя вертикальная структура карточки решают разные задачи. Не нужна фиксированная высота изображения без media-рамки.

Скажи на защите

Карточки растягиваются в пределах строки, внутри используется flex-column, а действие отодвигается вниз через auto-margin.

Типичная ошибка

Равнять карточки пробелами, пустыми абзацами или жёсткой высотой, которая обрезает длинный текст.

04Flexbox-навигация и меню без JavaScriptКак работает checkbox + :checked + соседний селектор.

Суть темы

В EsportsHub Bootstrap CSS предоставляет часть flex-разметки шапки. На широком экране ссылки видны в строке. Ниже 992px показан подписанный checkbox: его состояние управляет видимостью контейнера ссылок через CSS.

Браузер сам хранит checked-состояние и умеет переключать checkbox с клавиатуры. label for делает подпись кликабельной. Селектор input:checked ~ .menu выбирает последующий соседний элемент с тем же родителем. Если перенести menu перед input или вложить её в другую обёртку, этот селектор перестанет соответствовать разметке.

Поскольку CSS не меняет атрибут aria-expanded, не следует оставлять на таком контроле постоянно ложное значение. Нативная семантика checkbox сообщает checked/unchecked; aria-controls связывает его с меню, а пояснение объясняет назначение. Это иной механизм, чем Bootstrap Collapse.

<label for="menu-toggle">Menu</label>
<div id="menu" class="menu"><a href="events.html">Events</a></div>

/* Упрощённый пример для небольшого экрана */
.menu { display: none; }
#menu-toggle:checked ~ .menu { display: block; }
@media (min-width: 992px) {
  .menu { display: flex; }

05Bootstrap spacing и utility-классыКак прочитать mt-lg-4, px-sm-2, g-4 и ms-auto.

Суть темы

01. Чем HTML отличается от CSS?

HTML описывает структуру и смысл: заголовок, ссылка, форма. CSS управляет их видом и расположением. Один HTML можно оформить разными стилями, сохранив смысл.

02. Для чего нужен DOCTYPE?

Он выбирает стандартный режим отображения HTML. Это декларация типа документа, а не подключение библиотеки и не видимый элемент страницы.

03. Чем title отличается от h1?

Title называет документ во вкладке, истории и других интерфейсах браузера. H1 — главный заголовок в содержимом страницы.

04. Почему на сайте lang="en", а здесь lang="ru"?

Атрибут задаёт язык текста конкретного документа. EsportsHub содержит английский текст, а конспект — русский. Язык важен для произношения вспомогательными технологиями.

05. Почему section не заменяет любой div?

Section выделяет смысловой раздел и обычно имеет заголовок. Div — нейтральная обёртка для группировки и раскладки. Выбираю элемент по смыслу.

06. Когда нужен ol, а когда ul?

Ol — когда порядок шагов важен: найти турнир, проверить условия, подготовить регистрацию. Ul — для равноправных характеристик или списка игр.

Класс повторяется и подходит для компонентов; один элемент может иметь несколько классов. ID идентифицирует один элемент в документе, работает как якорь и имеет более высокую специфичность.

body — элемент, .player-card — класс, #contact-form — ID, table td — потомок. Могу найти каждое правило в css/style.css.

10. Почему позднее правило не всегда побеждает?

Порядок записи решает только при равенстве более ранних критериев каскада. Например, более специфичный селектор может победить менее специфичный, записанный позже.

11. Что наследуется в CSS?

Обычно цвет и параметры шрифта. Отступы и рамки обычно не наследуются. Наследование — не копирование всех стилей родителя.

12. Чем padding отличается от margin?

Padding находится внутри рамки, между содержимым и border; margin находится снаружи и отделяет блок от других. При border-box padding и border входят в заданную width.

13. Почему обычное фото нельзя просто сделать 300×100?

Если такое отношение сторон не соответствует исходнику, изображение растянется. Для обычного контента сохраняю height:auto; для превью задаю намеренную рамку и cover.

14. Чем cover отличается от contain?

Оба сохраняют пропорции содержимого. Cover заполняет область и может обрезать края, contain помещает изображение целиком и может оставлять свободное место.

15. Зачем alt, если картинка уже видна?

Alt передаёт её смысл при недоступности изображения и вспомогательным технологиям. Для действительно декоративного изображения alt пустой, чтобы не создавать лишний шум.

16. Что делает border-radius:50%?

Скругляет углы относительно размеров области. На квадрате получается круг, на прямоугольнике — овал. Поэтому у аватара сначала квадратная рамка.

17. Почему у label есть for, а у input name?

For связывает подпись с ID поля. Name задаёт ключ отправляемого значения. Это разные задачи; placeholder не заменяет ни одну из них.

18. Работает ли ваша форма без backend?

Да, как статический интерфейс с нативной проверкой и mailto. Она открывает почтовое приложение, но не хранит обращения и не гарантирует отправку или доставку.

19. Почему таблица прокручивается на телефоне?

Ей оставлена читаемая минимальная ширина. Прокручивается подписанный контейнер таблицы; документ не должен выходить за ширину экрана.

20. Почему для nav выбран Flexbox?

Бренд и ссылки естественно выстраиваются вдоль одной оси. Flexbox позволяет выровнять их по центру, распределить место и задать gap.

21. Что происходит с осями при flex-direction:column?

Главная ось становится вертикальной. Justify-content управляет распределением по ней, align-items — по горизонтальной поперечной оси.

22. Как вы выровняли высоту карточек?

Внешний flex-контейнер растягивает карточки в пределах строки. Внутри flex-column, у действия margin-top:auto. Текст может расти, изображение имеет свою рамку.

23. Почему для каркаса страницы нужен Grid?

Здесь важны одновременно строки и колонки: шапка сверху, sidebar слева, main справа и footer снизу. Именованные области показывают структуру прямо в CSS.

24. Зачем minmax(0,1fr), а не только 1fr?

Нулевая нижняя граница позволяет гибкому треку сжиматься, даже если содержимое имеет большую минимальную ширину. Самому содержимому тоже могут понадобиться перенос или overflow.

25. Чем CSS Grid отличается от Bootstrap Grid?

CSS Grid — нативная двумерная система display:grid. Стандартная Bootstrap Grid — готовая 12-колоночная система на Flexbox с классами container, row и col.

26. Как показать адаптивность 3/2/1?

Открыть Players и менять ширину: от 992px три custom-карточки, от 768px две, ниже одна. Затем показать flex-basis и две media queries.

27. Как прочитать col-md-6 col-lg-4?

От md колонка занимает 6/12, от lg — 4/12. В нашем полном примере также есть col-12 для узких экранов.

28. Что делает mt-lg-4?

Margin сверху 1.5rem от lg в стандартной шкале Bootstrap. Четвёрка — индекс шкалы, а не четыре пикселя.

29. Можно ли использовать Bootstrap после Assignment 1?

В заданном наборе требований Assignment 3 явно вводит Bootstrap. При этом сохраняются custom CSS и демонстрации Flexbox/Grid из первых работ.

30. Почему вы удалили bootstrap.bundle.min.js?

Финальное ограничение проекта — HTML и CSS. Поэтому сохранён Bootstrap CSS, а поведение Collapse и Carousel заменено нативным HTML/CSS. Я не утверждаю, что JS-плагины сейчас подключены.

31. Как работает меню без JS?

Checkbox хранит состояние; label его переключает; :checked и соседний селектор показывают контейнер ссылок. На desktop media query держит ссылки видимыми.

32. Как работает карусель без JS?

Панели стоят в flex-ленте с overflow-x:auto и scroll-snap. Нумерованные ссылки и Previous/Next ведут к уникальным ID; у первого и последнего есть переход по кругу.

33. Почему нельзя убрать outline?

Пользователь клавиатуры потеряет информацию о текущем фокусе. Вместо удаления я задаю видимый :focus-visible для ссылок, кнопок и полей.

34. Что делает prefers-reduced-motion?

Позволяет учитывать предпочтение пользователя уменьшить движение. В нашем CSS отключаются ненужные переходы и hover-трансформации; это не скрывает содержание.

35. Как доказать, что ссылка или компонент работает?

Не только показать класс: выполнить действие в браузере, проверить адрес или состояние, затем показать соответствующую разметку и CSS. Для изображений — проверить загрузку и пропорции.

36. Что ещё потребуется для настоящей платформы?

Учётные записи, проверенные команды/события, регистрация, хранение сообщений, результаты и правила расчёта рейтинга. Сейчас данные демонстрационные; лицензии старых изображений нужно отдельно подтвердить.
